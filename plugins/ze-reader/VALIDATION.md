## 原生问题的回归覆盖

首次加载发现 bootstrap 脚本上下文没有浏览器 DOM/计时器全局。已先添加失败测试，再改为使用工作台文档自己的 AbortController 和 Zotero 平台的异步让出方法。重新构建并从文件安装后，空视图、真实文献汇总、矩阵和标注跳转均正常。此差异不能仅靠给 Node VM 注入浏览器全局验证。

## 首版边界

自动化检查不代替外部翻译服务的真实连通性。分组、矩阵规则和令牌仅保存在当前电脑；阅读已读标签使用 Zotero 数据同步。未声明 Zotero 7、8、9 或 10.0.x 之外版本兼容。

## 最终审查与处理

对实现范围进行一次独立审查，完成一次集中修复，不重复派发审查。以下四项均先观察回归测试失败，再实现修复并通过完整回归；最终 XPI 已从修正后的源码重新构建。

1. 重要：Zotero 在端点处理前可能记录请求正文。桥接存续期间对调试入口中的 token 字段及当前令牌进行脱敏，覆盖转义与截断内容；卸载时仅恢复自己拥有的入口，不覆盖其他插件包装。
2. 重要：PDF 已在独立窗口打开时，原生 Reader 可能复用窗口而未建标签。分组恢复明确打开主窗口标签，并重新检查实际标签列表后才计入成功。
3. 重要：切换范围或刷新失败时旧矩阵仍可复制。开始读取即清空旧内容、禁用复制，仅在当前请求成功提交后启用。
4. 原审查为轻微，实施者按实际影响提升为重要：关闭工作台后，分组恢复的迟到结果可能重新启动大范围读取。已在刷新入口检查释放状态，阻止后续读取及 DOM 更新。

审查未判断的事项：真实外部翻译未测试，服务凭据、额度或提供方接口问题仍需自行验证；真实文库升级未执行，因此保留现有插件环境供用户自行测试；超出本机 Zotero 10.0.8 的兼容性未验证。完整进程重启已补充观察，但尚未核对重启后的全部工作台状态。用户要求停止电脑操作，之后不再进行原生界面测试。无延期处理的轻微代码问题。
